# 城市与地铁 · 新地图接入指南

> 依据仓库当前状态（`CFG.GAME_VERSION = 2.9.5`、`SAVE_VERSION = 2`、`TRAFFIC_MODEL = 6`、`RULES_REVISION = 17`）整理。
> 目标：回答三个问题——仓库怎么组织、新增一张地图要做什么、现有接口够不够用（怎样做到「不为一张地图新增接口」）。

---

## 0. 一页结论

1. **地图不是代码，是一份数据契约。** 一张地图 = 一个 `js/geo_xx.js`（几何）+ 一个 `js/data_xx.js`（玩法数据 + 注册对象），加上 `index.html` 里的两行 `<script>`。引擎不需要认识这张地图。
2. **新增一张地图的最小改动面是 3 个文件、2 行 HTML、1 条构建命令**：`js/geo_xx.js`、`js/data_xx.js`、`index.html`，然后 `node scripts/build.mjs`。不动任何引擎模块。
3. **现有接口的覆盖度很高**：16 个可随地图切换的配置键、8 大模块 33 个「城市特色机制」关键字（各三档强度）、完整的经济参数与事件库、区域/年代/规划/地标/设施/填海/限高、按需载入 + 缩略图 + 拼音自动本地化 + 车型兜底 + 背景铁路自动布线。**这些都是「写数据就能生效」**。
4. **真正会逼你改代码的只有三类**：① 地区风格表 `REGION_KEY`（`region` 不在表里会静默退化成中国内地风格）；② 逐城写死的表现参数（地方建筑标志、钟声、车辆配色、单一票价）；③ 验收侧一处写死的地图数量断言（`scripts/test-v24.mjs:14` 的 `MAP_ORDER.length === 15`）。
5. **想要「第 N 张地图零代码」**，把 §6 的 5 处一次性数据化改造做掉即可（总改动约 40 行，全部向后兼容）。之后再新增地图，代码侧只剩 `index.html` 两行。
6. **最大的真实成本不在代码，在地理数据**：仓库里没有 OSM → `geo_xx.js` 的转换工具（地理文件头注释写「由 OpenStreetMap 数据生成」，但生成器不在仓库内）。这一块要么自建一次性转换脚本（格式见 §3.2），要么手工构造小图（虚构地图可以直接用 `CM.Geo.enc` 编码）。

## 1. 仓库形态

**技术栈**：零构建依赖的静态站点。没有 `package.json`、没有打包器、没有 npm 依赖。`index.html` 按固定顺序加载 ~95 个 `js/*.js`，全部挂在全局 `window.CM` 上，各模块用 IIFE `(function (CM) { ... })(window.CM)` 扩展同一命名空间。渲染是 Canvas 2D，地面块与环境计算跑在 Web Worker（`js/tile-worker.js`），道路拥堵内核有 Rust 源（`src-sim/road.rs`）编译成 `js/road-worker.js`。

## 2. 一张地图在这套代码里是什么

### 2.1 三层数据

```
GEO（几何，可拆分按需载入）   DATA（玩法数据）        注册对象（展示 + 配置）
├ proj  {lon0,lat0,kx,ky}     ├ city / riverName        ├ id / name / title / sub
├ names[]                     ├ regions / plans         ├ facts / intro / features
├ water / roads / streets     ├ centers / rural         ├ highlights / tags / difficulty
├ rail / parks / reserves     ├ landmarks / facilities  ├ modes / kind / mapVersion
├ woods / admin / places      ├ events / histTasks      ├ geo / data
└ count                       ├ eras / roadYears …      ├ econ / cfg / cam
                              └ traits[]（城市特色）     └ extent（历史扩图）
```

### 2.2 注册与切换的生命周期

```
index.html
  ├─ js/geo_gz.js        ← 广州地理随页面载入（主菜单背景要用，所以不按需）
  ├─ js/geo.js           ← 解码器
  ├─ js/data_gz.js       ← 广州 DATA（maps.js 之后用它当默认）
  ├─ js/data_tutorial.js
  ├─ js/geo_xx.js (type="application/city-metro-geo")  ×14   ← 浏览器不执行，只作为声明
  ├─ js/data_xx.js                                    ×14   ← 登记 CM.MAP_LIST
  ├─ js/geo-index.js     ← 从上面这 14 条 script 生成索引（file / integrity / proj / names / places / count）
  ├─ js/terminals.js  js/traits.js  js/maps.js  js/data_eras.js
  └─ … js/menubg-data.js  js/menubg.js  js/main.js（必须最后）
```

进入地图时依次发生：

1. `CM.loadGeo(id)` 用 `<script>` 注入 `js/geo_xx.js`，校验 `water`/`roads` 数量与索引里的 `count` 一致，把 8 个 heavy 键补进同一个 `m.geo` 对象（`js/maps.js:256`）。失败重试一次，仍失败抛 `地图数据载入失败：<城市>`（`js/maps.js:266`，`error.code = 'GEO_LOAD'`）。
2. `CM.useMap(id)`（`js/maps.js:290`）把 `CM.mapId`、`CM.DATA`（逐键清空后 `Object.assign`）、`CM.GEO`、以及 16 个 `CFG_KEYS` 换成该地图的；再 `CM.Geo.init()` 与 `Metro.clearCaches()`。
3. 存档里只记 `meta.map`（地图 id）+ `meta.mapVersion`，逐格数组长度必须等于该图 `cfg.W * cfg.H`（`js/save.js` 会校验）。

### 2.3 `maps.js` 在你没写任何配置时替你做的事

注册循环 `for (const m of CM.MAP_LIST || [])`（`js/maps.js:56`）把每个登记对象归一化成 `CM.MAPS[id]`：

| 兜底 | 行为 |
| --- | --- |
| 配置基底 | 以广州 `GZ_CFG` 为底，`Object.assign(cfg, m.cfg)` 覆盖；**你只写差异项** |
| 出行参数平移 | 写了 `econ: { devOffset, money }` 时，用 `CM.deriveChoice` 把广州的 `choice` / `road.capGrowth` 曲线按年份平移、按货币缩放（香港用 `devOffset: 23, money: 0.25`） |
| 交通小区 | `cfg.ZONE` 缺省时 `autoZone(W,H)` 自动取 4/6/8/10/12/16/20/24（保证小区数 ≤ 2200，即交通计算量与跳月速度不随面积爆炸） |
| 超大型站 | `cost.station[t].XL` / `ops.stationDaily.XL` 缺省时按 L 的 1.6 / 1.7 倍补齐 |
| 城市经济 | `cfg.macro = m.kind === 'real' ? (m.cfg.macro || 'auto') : null`——真实城市默认启用通用经济，虚构图不启用 |
| 数据指纹 | `m.fp = fnv([id, W, H, water 数, roads 数, names 数, regions 的 id 串])`，写进存档 `meta.mapFp` |
| 坐标校正 | 真实城市按名称精确匹配，把铁路地标（3.2 格内）、铁路枢纽设施（3.6 格内）、任务与阶段锚点（12 格内）对齐到 OSM 同名站点 |
| 特色机制 | 对所有地图执行 `CM.Traits.compile(m)` |
| 排序 | `CM.MAP_ORDER`：`['tutorial','gz','hz','hk','tp','tk']` 优先，其余按注册顺序追加，最后按 `difficulty` 升序稳定排序 |

## 3. 新增一张地图：完整流程

### 3.0 先做决策

| 决策 | 影响 |
| --- | --- |
| 真实城市 / 虚构地图 | `kind: 'real'` ⇒ 必须有 `geo.proj`、必须声明 `use:'finance'`、默认启用城市经济、走 OSM 坐标校正；`fictional` 三者都不要求 |
| 范围与格网 | 每格 `CELL_M = 250` 米。`W × H` 决定内存与跳月速度；现有最大 212 × 164（伦敦 53 × 41 km）。新图建议先小后扩 |
| 起始年 | 决定 `CFG.START`、`growth` 曲线起点、`cost`/`ops`/`choice` 的量级 |
| 货币 | `cfg.money`（`code/unit/wan/yi/sym` + `eras[]` 时期换算），跨币制改革（英镑→便士、旧法郎→新法郎）用 `eras` |
| 难度 | `difficulty: 1–4`，同时决定地图选择页排序 |

### 3.1 第 1 步：准备地理数据 `js/geo_xx.js`

文件格式（`js/geo.js` 是唯一的格式说明者）：

```js
'use strict';
(function (CM) {
  (CM.GEOS = CM.GEOS || {}).xx = {
    proj: { lon0: 113.26, lat0: 23.13, kx: 1273.9, ky: 1436.6 },  // lon0/lat0 为地图左上角经纬度，kx/ky 为每度经纬的格数
    names: ['珠江', '白云山', …],                                  // 名称表，其余数组用下标引用
    water:   [ [0, 'o' + enc, 'i' + enc], [3, 25, enc] ],          // 多边形：环（o=外环, i=内环）；或 [名, 河宽, enc] 表示河道线
    roads:   [ [0, 1, flags, enc] ],                                // [名称下标, 等级, 标志位, 折线]
    streets: 'enc!enc!enc',                                         // 单字符串，用 ! 分隔
    rail:    [ [0, flags, enc, year] ],                             // year 可省
    parks:   [ [0, enc, enc] ],
    reserves:[ [0, enc, enc] ],
    woods:   [ [0, enc, enc] ],
    admin:   [ [level, 名称下标, enc] ],
    places:  [ ['体育西路', x, y, 0] ],                             // type：0 = 地铁站/地名，1 = 火车站
  };
})(window.CM);
```

要点：

- 坐标单位是**格**（250 m），折线用增量编码（×64、zigzag、每 5 位一字符、`+63` 偏移），`CM.Geo.enc(pts)` 就是编码器——虚构地图可以直接用它把坐标数组写成同样格式。
- `proj` 换算：`x = (lon − lon0) × kx`，`y = (lat0 − lat) × ky`。数据文件里通常再包一层 `ll(lat, lon)` 与 `at/anchor` 辅助函数（见 `js/data_hk.js:8-12`），写经纬度比写格坐标好维护。
- **必须**有 `proj`、`water`、`roads`（`scripts/geo-index.mjs` 会因此报「地图数据不完整」）。`names` 与 `places` 强烈建议有：前者给地图上的地名标注与英文本地化用，后者给坐标校正与站名匹配用。
- 单文件不得超 25 MiB（`build.mjs` 的 Cloudflare Pages 限制）。目前最大 `geo_tk.js` 4.9 MB。
- 仓库内**没有** OSM → 本格式的转换工具（现有文件的头注释写「由 OpenStreetMap 数据生成」，生成器在仓库外）。要么复刻一个一次性转换脚本，要么用虚构小图起步。

### 3.2 第 2 步：写玩法数据 `js/data_xx.js`

**`cfg` 可以写哪些键**（与 `CFG_KEYS` 对齐，`js/maps.js:7`）：
`W`、`H`、`ZONE`、`START`、`growth`、`money`、`econBase`、`cost`、`ops`、`fareDefault`、`fareRange`、`economy`、`macro`、`choice`、`road`、`workWeek`。
每个键的内部结构以 `js/config.js` 为准；最完整、最新的写法样板是 `js/data_ld.js:544-628`（伦敦，含通胀曲线、债券利率、GDP 参考数据、事件库覆盖）。

> 只需要「真实城市 + 通用经济」时，`cfg.macro` 可以完全不写——`maps.js` 会自动填 `'auto'`，`js/macro.js` 随即用通用参数（4 个全球事件：1973/1979 石油危机、2008 金融危机、2020 疫情），并在页面上标注「本地图使用通用经济参数（估算）」。

### 3.3 第 3 步：在 `index.html` 里登记两行

放在其它城市那一段（第 46–70 行那一片成对登记区），顺序如下：

```html
<script src="js/geo_xx.js" type="application/city-metro-geo"></script>
<script src="js/data_xx.js"></script>
```

- **`data_xx.js` 必须排在 `js/geo-index.js`（当前第 45 行）之后**。原因在数据文件开头那一行：`const G = CM.GEOS && CM.GEOS.xx; if (!G) return;`——索引还没建好时 `CM.GEOS.xx` 是 `undefined`，文件会**静默 return，地图不注册、也不报错**，只表现为地图选择页少一张图。这是最容易踩的坑。
- `geo_xx.js` 的位置其实不敏感：它的 `type="application/city-metro-geo"` 不是 JS MIME，浏览器根本不执行它，只是给 `scripts/geo-index.mjs` 的正则当标记用来抓「哪些文件是按需载入的地理数据」；`build.mjs` 会把它写进 `js/geo-index.js` 的索引（file/integrity/proj/names/places/count），进图时才由 `CM.loadGeo()` 注入。惯例是紧挨着对应 `data_xx.js` 放。
- 唯一例外是 `gz`：`js/geo_gz.js`（第 40 行）**没有** type 属性、不进索引、`geo.file` 也没有，由 `js/render.js:122` 的 `id === 'gz' ? 'geo_gz.js' : ...` 特判兜住。同理 `data_gz.js`（42）与 `data_tutorial.js`（43）排在 `geo-index.js` 之前，是因为它们**内联 GEO**、不读 `CM.GEOS`。
- 顺序硬约束（`scripts/verify-game.mjs:66-70` 会检查）：`js/config.js` → `js/maps.js`、`js/traits.js` → `js/maps.js`、`js/data_*.js` → `js/traits.js`、`js/maps.js` → `js/main.js`，且 `js/main.js` 必须是最后一个。
- 硬规则（`verify-game.mjs:83`）：`js/` 下**每个** `.js` 都必须被 `index.html` 引用，否则报「未引用的游戏脚本」。
- 现成的完整加载顺序（供对照）：40 `geo_gz` → 41 `geo.js` → 42 `data_gz` → 43 `data_tutorial` → 44 `geo_hz` → **45 `geo-index`** → 46 `data_hz` → 47–70 其余 13 对 geo/data → 71 `terminals` → 72 `traits` → 73 `maps` → 74 `data_eras` → … → 122 `menubg-data` → 123 `menubg` → 124 `main`。

| 政策与城市投资 `policy`（coin） | `investWindow` `austerity` `currency` | 投资窗口 / 财政紧缩 / 货币改革 |

| 交通结构与竞争 `transport`（road） | `rival` `modeChart` `corridors` `railTakeover` `roadRefill` `roadTransit` `carLimit` | 既有公交竞争 / 出行结构图 / 铁路与渡轮走廊 / 既有铁路接管 / 道路回填 / 路面公交竞争 / 限车政策 |
| 城市枢纽与大型活动 `hub`（train） | `hubMove` `portal` `cityLink` `tourism` `megaEvent` | 枢纽迁移 / 图外接驳 / 城市连接 / 旅游客流 / 大型活动 |
| 土地价值与站城开发 `land`（chart） | `railProperty` `foresight` `landBoom` | 沿线物业 / 提前布局 / 地价冲击 |
| 基础机制（不在特色页列出） | `finance` | 融资制度，`flavor` 取 au/us/sg/cn/hk/tw/fr/uk/jp 之一 |

强度只有三档：`level: 'light' | 'mid' | 'heavy'`，具体数值在 `js/traits.js` 的 `TIER` 表里（例：`austerity` 三档 = 拨款 ×0.9 / ×0.8 / ×0.5；`conserve` 重档 = 隧道 ×1.35、车站 ×1.3、拆迁 ×2）。

写一条就长什么样：

```js
{ use: 'conserve', level: 'heavy', star: true, icon: 'bridge',
  label: '泰晤士河与历史城区', text: '越江隧道与老城车站要避开保护区',
  regions: ['oldcity'], guards: ['…'], why: '《伦敦建筑与古建保护法》…' }
```

规则（`CM.Traits.validate`，构建时会跑）：

- `kind: 'real'` 必须有一条 `use: 'finance'`。
- 除 `finance` 这种 base 机制外，**每条都必须写 `why`**（史实依据），否则「缺史实依据」。
- `star: true` 的必须写 `text`（地图卡上的一句话），且**最多 3 条**（「招牌超过 3 项」）。
- 机制依赖的数据必须先存在（例：`scenic` 需要 `regions[].scenic`；`heightCap` 需要 `maxHeight`；`crossing` 需要 `cfg.cost.riverPerKm`；`reclaim` 需要 `data.reclaim`；`currency` 需要 `cfg.money.eras`；`archaeo` 需要已有 `conserve` 或 `guard`）。
- 事件只能**追加**到 `data.events` 末尾（存档按序号记录已触发），已有事件只补 `fx`——所以 traits 清单也要加在末尾。

## 6. 把「每张图改代码」压成「改一次数据」：5 处最小改造

原则：**每个改动都让缺省行为回落到现状**（不写新字段的地图表现完全不变），改动量小，收益是此后任何新地图零代码。

### 6.1 地区风格键（解决 A1）

三处 `REGION_KEY` 重复表 → 收敛为一处，并允许地图自带键：

```js
// js/maps.js（新增导出）
CM.REGION_KEY = { '中国内地':'cn', '中国香港':'hk', '中国台湾':'tw', '日本':'jp',
                  '法国':'eu', '英国':'eu', '新加坡':'hk', '美国':'eu', '澳大利亚':'eu', '…':'…' };
CM.regionKeyOf = m => (m && (m.regionKey || m.data.regionKey || CM.REGION_KEY[m.region])) || 'cn';
```
